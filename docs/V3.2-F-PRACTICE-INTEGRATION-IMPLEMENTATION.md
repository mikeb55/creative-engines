# V3.2-F — Practice integration

**Date:** 2026-10-16

## Handoff

`practice-studio-handoff` uses the same session storage and one-tick hold as the BHL hexatonic handoff. Sources are `generate`, `bhl`, `hexatonic`, and `pentatonic`. Any other source is rejected.

The stored object is a copy. Changing the caller’s MusicXML after send does not change the practice score. The handoff does not open or write a composition file. A path is rejected.

A named collection is resolved in the Scale Explorer. The mask is that registration transposed by the reference pitch class. A caller mask that disagrees is rejected. A caller status that disagrees is rejected. Provisional and advanced strings stay as registered.

## Buttons

- Generate: **Practice this score** sends the generated MusicXML, seed, and tuning preset.
- BHL: **Practice this candidate** sends the candidate MusicXML and, when a colour is selected, its transposed pitch-class set and status.
- Hexatonic Laboratory: **Practice this collection** sends the browser row’s pitch classes, registry id, and status.
- Pentatonic Engine: **Practice this collection** sends the manual colour, centre, and route seed.

`#/practice` reads the handoff once and shows the source, mask, root, tuning, and status.

## Tests

`tests/practiceHandoff.test.ts` covers score isolation, rejected sources, pentatonic transposition, provisional and advanced status, and page restore.
