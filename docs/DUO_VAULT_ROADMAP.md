# Duo Vault Roadmap

Canonical staged plan for wiring Tonality Vault into the `guitar_bass_duo` harmony path. Vault is the single harmonic authority. Each stage is independently shippable.

## Stages

- **Stage 0 — Audit (done).** Repo read, over-architected design shrunk to a thin first slice (pure resolver + tests); vault confirmed as single harmonic authority.
- **Stage 1 — Resolver (done).** `resolveDuoHarmonyForSymbol` with slash, alt, fallback; smoke tests for key symbols; musical PCs verified; committed as a clean reversible slice.
- **Stage 2 — Baseline capture (done).** Formal GCE + V3 gate on 5 representative duo progressions, vault not wired; scores + inputs stored as regression yardstick. See `DUO_VAULT_BASELINE.md`.
- **Stage 3 — Phrase-fill swap (done; verified safe, currently dormant).** Vault swap at `emitGuitarPhraseBar` (`guitarPhraseAuthority.ts:261`), gated to `presetId === 'guitar_bass_duo'` (`isStandardGuitarBassDuo`). Verified: resolver returns `source=vault` for all baseline symbols, tone pools genuinely differ from heuristic, swap is harmless and preset-scoped. **KNOWN LIMIT:** on the Stage 2 baseline seeds (esp. 50021), guitar v1 is ~87% motif-driven (`motifShape.ts:140`) and motif bars bypass `emitGuitarPhraseBar` — so line 261 never fires and the swap is **DORMANT**. Stage 3 does **NOT** prove "vault live in duo melody"; it prepares the phrase-fill path for bars/seeds that route through it.
- **Stage 4 — Motif tone sourcing + single-authority completion (the core of the milestone).** **FIRST target:** redirect the motif tone source (`motifShape.ts:140`) for `guitar_bass_duo` so vault pools feed the motif path that actually produces the duo melody on baseline seeds — this is where vault first becomes audible and measurable. **THEN** redirect the remaining downstream re-computers: `duoEnforcePhraseEndCadence` (`generateGoldenPathDuoScore.ts:2349`), `emitGuitarDuoIdentityBar7` (`guitarPhraseAuthority.ts:182`), `snapGuitarToChord` (`duoOrchestrationPass.ts:59`), `chordTonePitchesInRange` / `strictEnforceGlobalLeaps` leap-repair (`ecmShapingPass.ts`), `applyLateClosingGuitarContourNudge` (`6660`), `nudgeDuoGuitarPhraseEndsForVariety` (`6714`). Also fix canonical rewrite issues (e.g. unwanted `G7→G13`). Gate: no path re-derives tones from `chordTonesFromSymbol` or a parallel hierarchy; vault is sole authority on guitar v1; real harmonic movement vs the Stage 2 baseline appears and is measured here.
- **Stage 5 — Advanced chords + fallback policy.** Extend to maj7#11, alt dominants, etc.; define policy for unmapped extension chords (may invent phantom sevenths / drop add9 tones). Gate: advanced chords improve; fallback safely constrained or declined.
- **Stage 6 — Regression + adoption.** Re-run baseline GCE + V3, add listening checks; if simple/medium hold and advanced sound better, promote vault-backed duo path to default; docs/tests updated, old path legacy.
