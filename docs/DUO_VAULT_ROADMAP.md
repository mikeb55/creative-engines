# Duo Vault Roadmap

Canonical staged plan for wiring Tonality Vault into the `guitar_bass_duo` harmony path. Vault is the single harmonic authority. Each stage is independently shippable.

## Stages

- **Stage 0 — Audit (done).** Repo read, over-architected design shrunk to a thin first slice (pure resolver + tests); vault confirmed as single harmonic authority.
- **Stage 1 — Resolver (done).** `resolveDuoHarmonyForSymbol` with slash, alt, fallback; smoke tests for key symbols; musical PCs verified; committed as a clean reversible slice.
- **Stage 2 — Baseline capture (done).** Formal GCE + V3 gate on 5 representative duo progressions, vault not wired; scores + inputs stored as regression yardstick. See `DUO_VAULT_BASELINE.md`.
- **Stage 3 — Single integration swap (main phrase pool only).** Swap the guitar v1 tone source at `emitGuitarPhraseBar` (`guitarPhraseAuthority.ts:261`) to use `resolveDuoHarmonyForSymbol`, gated to `presetId === 'guitar_bass_duo'` only (use `isStandardGuitarBassDuo`, NOT `isDuoGoldenPathPreset`). Known limit: cadence snap, bar‑7 identity, orchestration snap, voice‑leading leap repair, closing‑contour nudge, and bar‑5 variety nudge still re‑derive tones from the old heuristic downstream, so vault covers non‑cadence phrase bars only at this stage. Gate: baseline scores HELD (not merely passing) — expect near‑flat movement; that flatness confirms the partial swap did no harm. V3 still PASS. Only the line‑261 site changed.
- **Stage 4 — Single‑authority completion + locked‑harmony cleanup (now the core of the milestone).** Redirect the downstream re‑computing steps to consume vault resolver output: `duoEnforcePhraseEndCadence` (`generateGoldenPathDuoScore.ts:2349`), `emitGuitarDuoIdentityBar7` (`guitarPhraseAuthority.ts:182`), `snapGuitarToChord` (`duoOrchestrationPass.ts:59`), `chordTonePitchesInRange` / `strictEnforceGlobalLeaps` leap‑repair (`ecmShapingPass.ts`), `applyLateClosingGuitarContourNudge` (`generateGoldenPathDuoScore.ts:6660`), `nudgeDuoGuitarPhraseEndsForVariety` (`generateGoldenPathDuoScore.ts:6714`), plus motif‑relative tone logic (`motifShape.ts:140`). Also fix canonical rewrite issues (e.g. unwanted `G7→G13`) on this path. Gate: no downstream step re‑derives tones from `chordTonesFromSymbol` or a parallel hierarchy; vault is the sole authority on the guitar v1 line; real harmonic movement vs the Stage 2 baseline appears and is measured here.
- **Stage 5 — Advanced chords + fallback policy.** Extend to maj7#11, alt dominants, etc.; define policy for unmapped extension chords (may invent phantom sevenths / drop add9 tones). Gate: advanced chords improve; fallback safely constrained or declined.
- **Stage 6 — Regression + adoption.** Re-run baseline GCE + V3, add listening checks; if simple/medium hold and advanced sound better, promote vault-backed duo path to default; docs/tests updated, old path legacy.
