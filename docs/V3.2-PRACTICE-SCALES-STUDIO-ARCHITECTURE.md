Behaviour:

- Curated tab lists the 20 pentatonic colours and the hexatonic tiers with their existing status strings. Mathematical sets stay on the other tab.
- Mathematical tab shows cardinality and pitch classes. It does not invent a scale name.
- A handoff chip names the source page and the colour or collection id. Clearing it drops the exercise source. It does not delete the source project.
- Fretboard uses `FretboardPanel`. Position is a fret window (`frets.from`, `frets.to`) plus the solver’s lowest fretted fret when a fingering exists.

- Audition uses `ScoreAudition`. Tempo control writes the tempo into the exercise MusicXML (`sound tempo` / `per-minute`) so the existing parser reads it. A separate metronome click is V3.3.
- Loop and repeat are transport controls around the existing player. They do not rewrite the score until the user exports.
- Difficulty on pentatonic material uses `PRACTICE_DIFFICULTIES`. Other sources show the source status instead of a fake grade.

## 4. Data model and persistence

### 4.1 Mathematical identity

A pitch-class subset is a bitmask integer.

- Bit *n* set means pitch class *n* is in the set. Bit 0 is C, bit 1 is C#, … bit 11 is B. This matches the binary numbering used by Ian Ring’s public scale catalogue.
- Mask `0` is the empty set.
- Mask `4095` (`0xFFF`) is the chromatic set.
- The power set has **4096** members (`0` … `4095`).

The brief’s figure of 2,048 subsets **including the empty set and the chromatic set** does not match either count:

- 4,096 is the full power set (empty and chromatic included).
- 2,048 is the count of masks with bit 0 set (a fixed tonic is present). That list **includes** the chromatic set (`4095`) and **excludes** the empty set (`0`). It includes the single-note set `{C}` (`1`).

V3.2 stores **4096** masks so the empty set and the chromatic set both exist. A filter “tonic fixed” shows the 2,048 masks with bit 0 set. The studio does not treat that filter as a list of musical scales.

`canonicalPitchSetId` stays the string identity when a set is handed to pentatonic or hexatonic code (`"0,2,4,7,9"`). The mask is the explorer key. Both must round-trip.

Ian Ring **names and catalogue numbers** are attached only after an independent check that the published entry’s binary equals this mask. Until that check, the mathematical row shows the mask, the cardinality, and the pitch classes. It shows no title. This repository has no verified Ring table today. Do not scrape or invent one in V3.2-B.

Forte numbers appear only for a 6-note set whose prime is in `FORTE_HEXACHORD_PRIMES`. Other cardinalities show no Forte label. `classifyPitchClassSet` is not called on them.

Provenance on every explorer row:

| Field | Values |
| --- | --- |
| `kind` | `curated` or `mathematical` |
| `mask` | `0` … `4095` |
| `curatedRef` | `{ registry, id }` or null |
| `status` | existing status string, or `MATHEMATICAL SET` |
| `displayName` | curated name, or null |
| `provenance` | copied from the registry row, or `Computed pitch-class subset. No musical name.` |

A curated row and a mathematical row may share a mask. They stay two rows. Equal pitch-class sets already stay separate when the musical object differs (`hex_major_omit_fourth` vs `maj9`).

## 5. Guitar fretboard and notation requirements

### 5.1 Fretboard

- Six strings. Open pitches come from standard MIDI or from `getAlternateGuitarTuningPreset`. A missing preset falls back to standard and the UI says so.
- Markers: scale tone, interval from the selected centre, chord tone (root / 3rd / 5th / extension only when a curated chord or triad supplied those roles). Mathematical sets get pitch-class markers only.
- Pentatonic pathways are the ordered intervals of the colour resource, drawn in one fret window. They are not a new pattern library.
- Dyads and triads are grips from `buildGuitarGripLibrary` or a realised triad pair, filtered to the fret window.
- Playable range: sounding pitch must sit in `guitarRange()` before it is a note. A grip wider than `SPAN_MAX` (4) or above fret 15 is shown as a warning, using the same limits as `pcFretboard`. The warning is not a playability approval.
- Fingering: if `pcFretboard` returns `ok` on standard tuning, show string and fret. Alternate tunings do not call `pcFretboard` until that solver takes open-string MIDI as an argument. Until then the panel shows pitches on the tuned board and the label `Fingering: not solved`.
- Playback highlight: extend `ScoreAudition` with an optional note callback (time, midi). The page maps sounding MIDI to board dots through `playbackNotes`. No second clock.

### 5.2 Notation

- One guitar staff by default. Duo exercises add the upright bass staff already produced by `generateHexatonicPhrase` or the BHL score. Do not invent a drum staff for the metronome in V3.2.
- No TAB staff. No chord-symbol staff unless the source MusicXML already has symbols. The studio does not add symbols.
- Tempo, metre, and bar count come from the exercise score. Looping does not change the file.
- Export is the exercise MusicXML, not the source composition. The source file’s hash is stored on the session and checked so a save cannot replace a WWH score, a BHL album source, or a hexatonic project.

### 5.3 Exercise kinds and the function each kind calls

| Kind | Implementation rule |
| --- | --- |
| Single-position scale | Pitches of the curated set inside `fretFrom`–`fretTo`, rhythm from a `RhythmSlot` template the user picked |
| Cross-position | Same pitches, window unlocked. On standard tuning, attach `pcFretboard` and show `hardShifts` |
| Intervals and cells | `transformCell` with the existing `CellTransform` union |
| Sequences | Repeated `transformCell` transposition inside the set. Stop at the guitar range |
| Dyad / triad | `buildGuitarGripLibrary` or the triad already on a WPS / provisional / advanced row |
| Rhythm and metre | `BhlRhythmTransform` applied to onsets of a copy. Metre values the MusicXML exporter already accepts |
| BHL transform | `applyHexatonicStrategy` or the shape helpers on a copy of the handed-off events. Strategy name stays `dialogue`, `liquid`, `sparse`, or `colour-remap` |
| Duo | Prefer an existing hexatonic or BHL guitar-and-bass score. `planLayeredField` may assign guitar and bass subsets of one field. It does not write a new duo engine |
| From a composition | `mapMotifPitches` from the handed-off line onto the selected collection. Original file untouched |

Seeds stay deterministic. No `Math.random()`.

## 6. Scale Explorer architecture

Two layers. One component.

**Curated layer.** Read-only views:

- Pentatonic: `listPentatonicColourResources()`.
- Hexatonic established: `listHexatonicCatalogue()` (11 scalars + 16 WPS pairs).
- Provisional: the 12 Core candidates. Status string required on every row.
- Advanced: `ADVANCED_COLOURS`.
- Explorer: `listExplorerCatalogue()` for the 50 hexachords. An Explorer row with no curated id is labelled by Forte number only, which this repo already computed and checked against music21 8.3. That Forte label is a class name, not permission to use the set as a scale.

**Mathematical layer.** For mask in `0..4095`, pitch classes are the set bits. Display spelling uses `PENTATONIC_NOTE_CHOICES` (sharp/flat convention already fixed: C, C#, D, Eb, E, F, F#, G, Ab, A, Bb, B). That spelling is a label for the pitch class, not a key signature.

Join: if a curated resource’s `canonicalPitchSet` equals the mask, the mathematical row lists those curated ids as links. It does not copy their names onto the mathematical row’s title.

Statuses travel with the link:

- Established catalogue rows keep their registry provenance.
- `PROVISIONAL — NOT MUSICALLY APPROVED`
- `ADVANCED — NOT MUSICALLY APPROVED`
- `EXPLORER — NOT MUSICALLY APPROVED`
- Mathematical-only: `MATHEMATICAL SET`

`artisticApproval` stays false. The explorer does not write `musicalQualityScore`.

Out of scope for the explorer: generating names for the unnamed masks, importing Ian Ring prose, and promoting a provisional pair.
