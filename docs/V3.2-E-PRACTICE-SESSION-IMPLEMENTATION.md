# V3.2-E — Practice sessions and playback

**Date:** 2026-10-16

## Playback

`#/practice` plays the generated exercise through `ScoreAudition` and `playbackEngine`. That is the same Tone.js Transport used by Generate, BHL, and the Hexatonic Laboratory. Starting playback stops whatever that Transport was already playing.

Repeat places the same notes again on that Transport. Loop uses `transport.loop` for one pass. The metronome is a second synth on the same Transport. It is not a part in the MusicXML.

Tempo is written into `<sound tempo>` and `<per-minute>`. The parser reads that number back. Changing tempo does not rebuild the notes.

`barQuarters` is `beats × 4 / beat-type`. A 6/8 bar is 3 quarters and 6 metronome clicks. A 4/4 bar stays 4 quarters.

## Score and files

`practiceExerciseToMusicXml` calls `exportScoreModelToMusicXml`. `ScorePreview` shows the result with tabs off.

`practice-session` version 1 stores the MusicXML and its SHA-256. Reopen checks the hash and does not call the generator. A changed score is rejected.

Desktop write uses the existing `saveExportFile` path `Composer OS Exports/Practice Studio/`. Open File uses `openFileDefaultApp`. Open in Finder uses `showItemInFolder`. The browser downloads the file and those two buttons say they need the desktop app.

No composition file is opened or rewritten by a session save.

## Tests

`tests/practiceSession.test.ts`: 4/4 and 6/8 durations, pitch-class membership, tempo scaling, repeat offset, metronome click count, save/reopen, and a rejected hash.
