## 2. TypeScript UTF-16 issue

File left unchanged: `apps/composer-os-app/src/components/mosaic-import/barryHarrisChordMelodyUi.ts`.

| Fact | Value |
| --- | --- |
| Blob | `214e1f3a66697a0b000363549c1f02926c4d818d`, mode `100644` |
| Introduced | `31c8d51c` (V80). Plain ASCII helpers. |
| Bytes | 2178. No BOM. Starts `2f 00 2a 00 2a 00 20 00` (`/** ` in UTF-16 LE). NUL ratio about 0.5. |
| Prior note | V3.1-E said bytes `47 00 42 00`. That sequence is not in this blob. |
| Git attributes | `text`, `working-tree-encoding`, and `diff` are unspecified. Git stores the UTF-16 bytes as-is. |
| `tsc -p apps/composer-os-app/tsconfig.json --noEmit` | exit 2. **826** errors, all in this file: TS1127 × 769, TS1128 × 48, TS1109 × 7, TS1161 × 1, TS1005 × 1. First diagnostic is line 1. |
| Imports | None. `MosaicStyleTransferResults.tsx` already contains the same two functions in UTF-8. `tsconfig` `include` still typechecks the orphan file. |

UTF-16 is not intentional. The text has no character that needs it. A Windows save during V80 is the likely cause. TypeScript reads the file as UTF-8, so every other byte is NUL or an invalid character, and the parser emits one diagnostic per broken token.

**Safest correction, not applied:**

1. Decode UTF-16 LE to UTF-8 with no BOM. Keep LF. Do not add `working-tree-encoding=utf-16`; that would keep surprising `tsc` on machines that do not apply the attribute.
2. Commit that conversion by itself. Git will show a full-file rewrite because every stored byte changes. History of blob `214e1f3a` stays reachable. There is no CRLF contract on this path.
3. Re-run `tsc --noEmit` and confirm the 826 errors are gone and no other file appears.
4. Do not expect a new desktop package from that commit. Nothing imports the file, so Vite and the staged bundles do not contain it.

## 3. Current installer

Script: `apps/composer-os-desktop/install/installComposerOsDesktopMac.ts`. npm script: `desktop:install:mac`. Not run.

It only looks under `apps/composer-os-desktop/release/` (`release/`, `release/mac`, `release/mac-arm64`, `release/mac-x64`). The V3.1-E app is in `release-v31e-46ad0e52/`. The app currently in `release/mac-arm64/` is stamp `7df4c1f47c93f7c85f24dc4ef5ea835471debd9b`, generated `2026-10-15T18:55:45.123Z`. Running the script now would replace `/Applications/Composer OS Desktop.app` with that older build.

Exact order:

1. Quit `"Composer OS Desktop"` with `osascript`, then `pkill -f "Composer OS Desktop"`. A failed quit is ignored. `pkill -f` can match any command line that contains that string.
2. Spin for 800 ms. It does not wait until the process is gone.
3. If `/Applications/Composer OS Desktop.app` exists, `fs.rmSync` it recursively. No copy is kept.
4. `ditto` the release app onto that path.
5. Ad-hoc `codesign --force --sign -` on each `Versions/A` framework, each helper `.app`, then the bundle. This replaces whatever signature was there. `codesign --deep` is intentionally avoided.
6. `xattr -dr com.apple.quarantine` on the installed app. A missing attribute is ignored.
7. `codesign -dv` on the installed app.
8. `open -a` the installed app. The script then prints `Launched: yes`.

Rollback limit: after step 3 the previous app is gone. A failed `ditto`, `codesign`, or launch leaves no previous bundle to put back. There is no stamp check, no hash check, and no “do not launch” mode.

## 5. Proposed install (do not run until explicitly authorised)

Do not use `desktop:install:mac` for this package. Do not write to the Samsung T7. Do not delete `/Applications/Composer OS Desktop.app` until a restore copy has been checked.

1. Quit Composer OS Desktop. Confirm no process whose executable is that app.
2. Read the installed app’s `Contents/Resources/composer-os-build-stamp.json` and record `gitCommit`.
3. `ditto` `/Applications/Composer OS Desktop.app` to a local rollback directory that is not `/Applications` and not the T7, for example `~/ComposerOsDesktop-rollback/<installed-commit>/Composer OS Desktop.app`.
4. On that copy, confirm the app bundle exists, `codesign -dv` still reports a signature, and the stamp `gitCommit` matches step 2. If any check fails, stop. The installed app is still the live one.
5. `ditto` `apps/composer-os-desktop/release-v31e-46ad0e52/mac-arm64/Composer OS Desktop.app` to a staging directory, also outside `/Applications`, for example `~/ComposerOsDesktop-staging/Composer OS Desktop.app`.
6. Ad-hoc sign that staging copy inside-out, the same order as `adhocSignMacApp` (framework `Versions/A`, helper `.app`, then the bundle). Clear quarantine on the staging copy only. Confirm its stamp `gitCommit` is `46ad0e52130bec5af79e62c519d9500276ecd845` and the two bundle SHA-256 values above.
7. `open` the staging app. Confirm it launches and the stamp is still `46ad0e52`. That launch is not musical approval.
8. Only then swap `/Applications`: move the live app aside if it is still there, `ditto` the verified staging app into `/Applications/Composer OS Desktop.app`, sign and clear quarantine on that installed copy, and open it once.
9. Restore if the installed copy fails: quit it, remove only the new `/Applications/Composer OS Desktop.app`, and `ditto` the rollback app from step 3 back. Confirm the restored stamp equals step 2 before calling the restore done.
