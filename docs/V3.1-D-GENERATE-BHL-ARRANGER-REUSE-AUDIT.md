## Page purposes (keep these distinct)

| Page | Route | Job |
| --- | --- | --- |
| Generate | `#/` | Start songs and instrumental compositions from composer, form, and preset choices. |
| BHL Composer | `#/bhl` | Develop a locked bass with hexatonic or world colour, motif, and contrasting guitar candidates. |
| Arranger | `#/arranger` | Take existing MIDI or MusicXML and restyle it through the Generate request. |

Hexatonic (`#/hexatonic`), Pentatonic (`#/pentatonic`), and Evaluation (`#/evaluation`) stay specialist pages. They hand work across. They are not a fourth composition engine.

## What is already shared

- Hash routes in `appRouter.ts`. One shell, one nav.
- `sessionStorage` handoff in `bhlHexatonicHandoff.ts`: Hexatonic → BHL, BHL → Evaluation. An in-memory hold covers React StrictMode’s second read. Hosts without `sessionStorage` no longer throw.
- `ScoreAudition` and `ScorePreview` for Hexatonic and BHL.
- Arranger builds a `GenerateRequest`. It does not own a second generator.
- Hexatonic phrase generation is called by the Hexatonic page and by blind-audition excerpts. BHL does not call `generateHexatonicPhrase` to write its guitar. BHL remaps or applies Dialogue / Liquid / Sparse on its own event list.
- Triadic neighbours live in `triadicTransformation.ts`. The laboratory can hand a registered pair to BHL. It does not start a new composer.

## Safe handoff for later (do not build now)

1. Keep MusicXML as the musical object that moves between pages.
2. Keep a small JSON stamp beside it: colour id, family, reference pitch class, strategy or `colour-remap`, provisional flag, seed, world. The BHL project file and the MusicXML comment already carry this.
3. Use the existing handoff functions for in-app jumps. Use the project file when the jump must survive a reload.
4. Arranger and Generate already share `GenerateRequest`. A future “arrange this BHL export” action should drop the MusicXML on Arranger’s existing upload. It should not call BHL from Arranger.
5. Do not add a universal scale engine, a second hexatonic writer, or a merged melody engine in V3.1.

## Duplication that was not “fixed”

No overlapping function was small enough, and safe enough, to delete during this verification. The `sessionStorage` guard is a crash fix, not a deduplication.
